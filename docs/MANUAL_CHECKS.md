# Ручная проверка и демонстрация

Запустите сервер и клиент по [README](../README.md). Используйте `http://127.0.0.1:5173`. Все данные и пароли ниже демонстрационные.

## Основные сценарии

| № | Действия | Ожидаемый результат |
| --- | --- | --- |
| 1 | Войти как `employee` / `demo-user`, спросить «Отпуск» | Ответ содержит «14 календарных дней», источник «Оформление отпуска» |

| 5 | Выйти, войти как `hr` / `demo-hr`, спросить «Премирование» | Ответ про 120000 и ссылка «Правила премирования»; источник открывается |

## Подмена роли и отсутствие сессии

Войдите как `employee`, откройте DevTools → Console на странице приложения и выполните:

```javascript
const roleInBody = await fetch('/api/ask', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ question: 'Резервирование', role: 'admin' }),
});
console.log(roleInBody.status); // 422

const roleInHeaders = await fetch('/api/ask?role=admin', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json', 'X-Role': 'admin' },
  body: JSON.stringify({ question: 'Резервирование' }),
});
console.log(roleInHeaders.status, await roleInHeaders.json());
// 200, { answer: 'Недостаточно данных', sources: [] }

const noSession = await fetch('/api/ask', {
  method: 'POST',
  credentials: 'omit',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ question: 'Отпуск' }),
});
console.log(noSession.status); // 401
```

`credentials: 'omit'` проверяет запрос без cookie, не завершая текущую браузерную сессию. Дополнительные клиентские поля не должны использоваться как источник полномочий.

## Ошибка сервиса

Специального режима сбоя в приложении нет. Проверки разделены:

- Сервер: из `backend` выполнить `.\.venv\Scripts\python.exe -m pytest -v tests/test_rag.py::test_unavailable_model_returns_safe_error`. Зависимость модели подменяется моделью, выбрасывающей исключение; проверяется реальная обработка API и отсутствие внутренней диагностики в ответе.
- UI: из `frontend` выполнить `yarn test:e2e -g "ошибка сервиса"`. Playwright возвращает HTTP 503 для `/api/ask`, проверяет сообщение, снимает перехват и проверяет успешную повторную отправку. Это тест интерфейса с подменой сетевого ответа.

Перед браузерным тестом остановите ручные процессы Vite и Uvicorn, поскольку Playwright запускает собственные серверы.

## Короткий сценарий защиты

1. Показать чистую копию, инструкции установки и SHA сдаваемого коммита.
2. Запустить FastAPI и Vite в двух терминалах.
3. Успех: `employee` → «Отпуск» → открыть источник.
4. Ошибка: тот же пользователь → прямой URL `/documents/hr-2` → отказ без текста документа.
5. Показать в Network тело `/api/ask`, состоящее только из `question`.
6. По схеме объяснить: сессия → серверная роль → фильтрация → поиск → mock → источники. Указать повторную проверку прямой ссылки.
7. Открыть тест, который записывает контекст модели, и показать, где проверяется отсутствие закрытых источников.

## Подготовка к небольшому изменению

- Изменение политики доступа: `DocumentStore.available_to()` и ожидаемая матрица в `test_rag.py`.
- Изменение поиска: `rag/utils.py` и `rag/service.py`; сохранить фильтрацию до поиска и модели.
- Изменение текста: `app/data/documents.json`, затем перезапуск сервера и проверка затронутых ожиданий.
- Изменение API: серверные Pydantic-схемы и соответствующие клиентские схемы Yup.

После изменения выполнить затронутые серверные тесты; при изменении контракта или UI — соответствующий E2E-сценарий. Не расширять права только скрытием или показом элементов интерфейса.
