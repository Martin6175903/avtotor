# Автотор: локальная база знаний с проверкой доступа

В рамках тестового задания разработал прототип интеграции React-интерфейса с локальным RAG-сервисом на FastAPI. Пользователь задаёт вопрос, сервер выбирает доступные ему документы и возвращает детерминированный ответ со ссылками на источники.

Все шесть документов, учётные записи и описанные процедуры синтетические и не отражают реальные внутренние правила компании «Автотор». Для работы приложения не требуются внешние LLM, API-ключи и векторная база данных.

## Возможности

- Вход в тестовую серверную сессию, восстановление сессии после перезагрузки страницы и выход.
- Приём вопроса через `POST /ask` с телом `{ "question": "..." }`.
- Определение пользователя и роли на сервере по действующей сессии.
- Фильтрация документов по правам до поиска и передачи контекста mock-модели.
- Ответ «Недостаточно данных» с пустым списком источников, если разрешённых совпадений нет.
- Повторная проверка доступа при прямом открытии документа.
- Отображение ответа, источников, состояния загрузки и ошибок сервиса.
- Очищение предыдущего ответа при смене пользователя.

## Установка

Для установки необходимы Git, Python, Node.js и Yarn Classic. Установка Yarn при его отсутствии:

```powershell
npm install --global yarn@1.22.22
```

Клонирование репозитория:

```powershell
git clone https://github.com/Martin6175903/avtotor.git
cd avtotor
```

### Сервер

Из корня репозитория:

```powershell
cd backend

python -m venv .venv

.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Команды используют интерпретатор виртуального окружения напрямую, поэтому его активация необязательна.

### Клиент

В отдельном терминале из корня репозитория:

```powershell
cd frontend

yarn install --frozen-lockfile

yarn playwright install chromium
```

Chromium необходим для браузерных тестов. Для ручного запуска интерфейса достаточно установленного браузера.

Первичная установка зависимостей требует интернета. После установки приложение работает локально без обращений к внешним модельным сервисам. Файл `.env` для запуска не требуется.

### Особенности Linux и macOS

Путь к его интерпретатору — `./.venv/bin/python`. Клиентские команды остаются такими же. Приведённые ниже команды запуска и проверки записаны для проверенной Windows-среды.

## Запуск

Терминал 1, папка `backend`:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Терминал 2, папка `frontend`:

```powershell
yarn dev --host 127.0.0.1
```

| Сервис | Адрес |
| --- | --- |
| Интерфейс | http://127.0.0.1:5173 |
| Проверка состояния сервера | http://127.0.0.1:8000/health |
| OpenAPI / Swagger UI | http://127.0.0.1:8000/docs |

Vite проксирует `/api/*` на FastAPI и удаляет префикс `/api`. Например, браузер отправляет запрос на `/api/ask`, а сервер обрабатывает маршрут `/ask`.

Сессия привязана к cookie выбранного хоста. При переходе между `localhost` и `127.0.0.1` потребуется отдельный вход.

Прототип рассчитан на один процесс Uvicorn. Сессии хранятся в памяти и теряются после перезапуска сервера. Срок действия сессии — один час, без автоматического продления при каждом запросе.

## Тестовые учётные записи

Реквизиты предназначены только для демонстрации прототипа.

| Логин | Пароль | Серверная роль | Доступ |
| --- | --- | --- | --- |
| `employee` | `demo-user` | `user` | 3 общедоступных документа |
| `hr` | `demo-hr` | `hr` | Общедоступные и 2 HR-документа |
| `admin` | `demo-admin` | `admin` | Общедоступные и 1 административный документ |

Роли независимы: администратор не получает автоматический доступ к HR-документам.

Общедоступные документы доступны всем вошедшим пользователям. Анонимный доступ к документам запрещён.

## Документы

Исходный корпус хранится в `backend/app/data/documents.json`.

| ID | Название | Роль доступа |
| --- | --- | --- |
| `public-1` | О компании Автотор | `public` |
| `public-2` | Оформление отпуска | `public` |
| `public-3` | Обращение в техподдержку | `public` |
| `hr-1` | Подбор сотрудников | `hr` |
| `hr-2` | Правила премирования | `hr` |
| `admin-1` | Резервирование данных | `admin` |

При запуске сервер проверяет структуру записей, уникальность ID и распределение документов по ролям: 3 общедоступных, 2 HR и 1 административный.

Корпус читается один раз при запуске. Изменения JSON-файла применяются после перезапуска сервера.

## Контракт API

Пути указаны относительно FastAPI на порту `8000`. При обращении через Vite используется префикс `/api`.

| Метод и путь | Тело запроса | Результат |
| --- | --- | --- |
| `GET /health` | — | `200`, `{ "status": "ok" }`; сессия не требуется |
| `POST /auth/login` | `{ "username": "employee", "password": "demo-user" }` | `200`, пользователь и cookie; неверные реквизиты — `401` |
| `GET /auth/me` | — | `200`, текущий пользователь; без действующей сессии — `401` |
| `POST /auth/logout` | — | `204`, отзыв сессии и удаление cookie; повторный выход допустим |
| `POST /ask` | `{ "question": "Отпуск" }` | `200`, ответ и источники; ошибки — `401`, `422` или `503` |
| `GET /documents/{id}` | — | `200`, `{ id, title, text }`; без сессии — `401`; закрытый или отсутствующий документ — `404` |

### Запрос вопроса

`POST /ask` принимает только поле `question`: строку длиной от 1 до 2000 символов после удаления пробелов по краям.

Дополнительные поля, включая `role` и `userId`, отклоняются с `422`. Роль в query-параметрах и заголовках не используется для авторизации.

Пример запроса:

```json
{
  "question": "Отпуск"
}
```

Пример успешного ответа:

```json
{
  "answer": "Отпуск оформляется через заявление руководителю. Подайте заявление не позднее чем за 14 календарных дней до начала отдыха.",
  "sources": [
    {
      "id": "public-2",
      "title": "Оформление отпуска",
      "url": "/documents/public-2"
    }
  ]
}
```

`sources[].url` указывает на страницу документа в интерфейсе. Она запрашивает текст через `/api/documents/{id}`, после чего сервер повторно проверяет доступ. Клиент строит внутреннюю ссылку из проверенного ID документа.

Если разрешённых совпадений нет, сервер возвращает `200`:

```json
{
  "answer": "Недостаточно данных",
  "sources": []
}
```

В этом случае модель не вызывается.

### Сессия и авторизация

Cookie `rag_session` содержит случайный непрозрачный идентификатор сессии. Пользователя и роль сервер определяет по собственным данным.

Параметры cookie:

- `HttpOnly`;
- `SameSite=Lax`;
- `Path=/`;
- `Max-Age=3600`;
- `Secure=False` для локального HTTP.

Ответы сервера имеют заголовок `Cache-Control: no-store`.

Для запрещённого и отсутствующего документа API возвращает одинаковый `404` с сообщением «Документ не найден или недоступен.».

## Поиск и mock-модель

Обработка вопроса выполняется последовательно:

1. Сервер получает пользователя из действующей сессии.
2. `DocumentStore.available_to()` оставляет только разрешённые документы.
3. Поиск сопоставляет слова вопроса со словами заголовка и текста документа. Используются приведение регистра, токены из букв и цифр длиной от трёх символов и исключение стоп-слов.
4. Оценка документа равна числу общих уникальных слов. Совпадения сортируются по убыванию оценки, затем по ID.
5. В модель передаются вопрос и только разрешённые контексты `id/title/text`.
6. `DeterministicMockModel` соединяет тексты источников, разделяя их пустой строкой. Сервер формирует ссылки из того же набора контекстов.

Поиск не учитывает синонимы и словоформы. Mock не обучается и не выполняет смысловую генерацию. Эти упрощения позволяют проверить интеграцию, происхождение ответа и разграничение доступа.

[Границы mock и изменения для реальной интеграции](docs/INTEGRATION.md#границы-mock-и-переход-к-реальной-интеграции).

## Автоматические проверки

### Сервер

Из папки `backend`:

```powershell
.\.venv\Scripts\python.exe -m pytest -v
```

Серверные тесты проверяют:

- создание, завершение и истечение сессии;
- отклонение поддельной сессии;
- матрицу доступа и прямое открытие документов;
- попытки подмены роли;
- валидацию запроса;
- отсутствие закрытых источников в ответе, ссылках и контексте модели;
- отсутствие вызова модели при отсутствии разрешённых совпадений;
- детерминированность ответа;
- безопасную обработку ошибки модели.

### Клиент

Из папки `frontend`:

```powershell
yarn lint
yarn build
yarn test:e2e
```

Playwright самостоятельно запускает FastAPI и Vite, используя окружение `backend/.venv`. Для запуска E2E порты `5173` и `8000` должны быть свободны: повторное использование уже запущенных серверов отключено.

Тесты выполняются в Chromium, одним worker, без автоматических повторов.

Просмотр HTML-отчёта:

```powershell
yarn test:e2e:report
```

Интерактивный запуск:

```powershell
yarn test:e2e:ui
```

Основные E2E-сценарии используют работающий FastAPI. В сценарии ошибки сервиса Playwright подменяет ответ `/api/ask` на HTTP 503 и проверяет отображение ошибки и повторную отправку вопроса. Обработку исключения самой модели проверяет отдельный серверный тест.

## Ручная проверка

| Сценарий | Действия | Ожидаемый результат |
| --- | --- | --- |
| Ответ с источником | Войти как `employee`, задать вопрос «Отпуск» | Ответ про оформление отпуска и ссылка на документ |

| Административный документ | Войти как `admin`, спросить «Резервирование» | Ответ и доступный административный источник |

## Ограничения

Прототип использует статические тестовые аккаунты, сессии в памяти одного процесса и фиксированный корпус из шести документов. Полноценная аутентификация, управление документами, реальная LLM, production-инфраструктура и CI не реализованы.

Подробные решения, компромиссы и необходимые изменения для реального использования описал в [NOTES.md](NOTES.md).
